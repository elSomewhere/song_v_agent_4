# Midjourney Mode Implementation Plan for VC-RAG-SBG

## Overview

This plan adds a "midjourney" mode to the VC-RAG-SBG system that:
1. Preserves the existing preprocessing pipeline (script, refs, entities parsing)
2. Generates contextual prompts in the standard `./prompts` folder
3. Converts these prompts to midjourney-optimized versions using a GPT agent
4. Outputs midjourney prompts to a new `./prompts_midjourney` folder
5. Skips actual image rendering (gpt-image-1) when midjourney mode is active

## Architecture Changes

**File**: `run.py`
**Changes**: Add new command line argument

```python
    # ... existing overrides ...
```

### 3. Workflow Modification
**File**: `run.py` - `build_workflow()` function
**Changes**: Conditional workflow routing

**Current Flow**:
```
renderer → fast_qa → vision_qa → policy → memory_update
```

**New Midjourney Flow**:
```
renderer (prompt-only) → midjourney_converter → memory_update
```

**Implementation**:
```python
def build_workflow() -> StateGraph:
    """Build workflow with midjourney mode support."""
    
    # ... existing nodes ...
    graph.add_node("midjourney_converter", midjourney_converter_node)
    
    # Conditional edges based on midjourney mode
    graph.add_conditional_edges("renderer", 
        lambda state: "midjourney_converter" if state.config.get("midjourney_mode") 
                     else "fast_qa")
    
    graph.add_edge("midjourney_converter", "memory_update")
```

## Detailed Implementation Steps

### Phase 1: Core Infrastructure (1-2 hours)

1. **Add Command Line Flag**
   - Modify `run.py` argument parser
   - Add midjourney_mode to config_overrides
   - Test argument parsing

2. **Create Midjourney Converter Node**
   - Create `src/nodes/midjourney_converter.py`

   - Add to workflow graph with conditional routing

3. **Modify Renderer for Prompt-Only Mode**
   - Add midjourney mode detection in renderer_node
   - Implement _generate_prompt_only function
   - Ensure prompts are still saved to ./prompts folder

### Phase 2: Prompt Optimization Engine (2-3 hours)

1. **Midjourney Prompt Engineering**
   - Research midjourney best practices and syntax
   - Design GPT-4o system prompt for conversion
   - Handle midjourney parameters (--ar, --stylize, --chaos, etc.)

2. **Prompt Conversion Logic**
   ```python
   def convert_to_midjourney_prompt(raw_prompt: str, style_context: str,
   ```

3. **Handle Midjourney Constraints**
   - Character/word limits
   - Parameter syntax validation
   - Style keyword optimization
   - Aspect ratio handling

### Phase 3: Integration & Testing (1-2 hours)

   - Test midjourney mode end-to-end
   - Ensure preprocessing pipeline still works
   - Verify prompt generation and conversion
   - Test output folder structure

2. **Output Management**
   - Create `./prompts_midjourney` folder structure
   - Match naming convention with original prompts
   - Ensure proper file organization

3. **Error Handling**
   - Handle GPT-4o API failures gracefully
   - Validate midjourney prompt syntax
   - Provide fallback prompts if conversion fails

## Benefits

1. **Preserves Existing Pipeline**: All preprocessing and contextual analysis remains intact
2. **Leverages Contextual Intelligence**: Midjourney prompts benefit from entity recognition, reference images, and style analysis
3. **Maintains Consistency**: Character descriptions and visual context carry through to midjourney prompts
4. **No Breaking Changes**: Existing functionality remains unchanged
5. **Cost Effective**: Skips expensive image generation while preserving prompt intelligence
6. **Flexible Output**: Users can use midjourney prompts directly or as starting points for further refinement

## Cost Analysis

**Standard Mode**: ~$35-50 per run (includes image generation)
**Midjourney Mode**: ~$8-12 per run (prompt generation + conversion only)

**Savings**: ~75-80% cost reduction while preserving intelligent prompt generation
